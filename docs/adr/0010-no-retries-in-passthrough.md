# 0010. Passthrough mode does not retry or circuit-break

- Status: Accepted
- Date: 2026-09-26

## Context

In passthrough mode (feature 03) the Callsheet proxy sits between an agent and
its model provider. API gateways often add retries and circuit breakers. Here
that would change what the agent sees:

- The agent already has its own retry and back-off logic. A proxy retry
  stacks on top of it, multiplies load during an outage, and can spend budget
  on requests the agent never knows were sent twice.
- A circuit breaker would answer with Callsheet-made errors while the provider
  is healthy for other clients, so the agent reacts to Callsheet instead of the
  provider.
- Casting (feature 11) needs the provider's real 429 and `Retry-After`
  signals, which a retrying proxy would hide.

`docs/DECISIONS.md` (decision 11) and `docs/RESEARCH.md` §5 ("Gateway circuit
breaker: rejected in passthrough: it changes agent-visible behaviour") already
record this choice; it had no ADR.

## Decision

- In passthrough mode the proxy sends each client request upstream exactly
  once. It never retries, and it has no circuit breaker.
- Upstream responses, including error statuses, error bodies and headers such
  as `Retry-After`, reach the client unchanged. The client owns retries.
- Callsheet may still refuse a request itself, for its own reasons: budget
  (feature 05) or rate limit (feature 06). That refusal is a 429 with
  `Retry-After` generated by Callsheet, and the event log records it as
  Callsheet's decision, not the provider's (ADR 0005 pins the format).

## Consequences

- An agent behaves the same with or without Callsheet in front of it, apart
  from Callsheet's own enforcement.
- Provider outages show up in the recorded data exactly as the agent saw
  them, which feature 11 needs.
- Transparency tests for feature 03 must check that an upstream error passes
  through unchanged and is sent upstream only once.
- Retries or failover can only be added in a separate, explicitly enabled
  mode, and that needs a new ADR.
